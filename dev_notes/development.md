# Development setup and checks

## Requirements

- Python 3.12 or newer
- [uv](https://docs.astral.sh/uv/)
- A running Docker daemon, for the full test suite (PostgreSQL and Redis tests)

## Setup

```sh
git clone https://github.com/AbdullaK123/wire_rpc
cd wire_rpc
uv sync --locked
```

The default dev dependency group includes every optional extra (argon2, PyJWT,
redis, asyncpg), the type checker, the linter and the test tools.

## The checks CI runs

```sh
uv run --locked pyrefly check            # type checking
uv run --locked ruff check               # pyflakes and import order
uv run --locked pytest -q -W error       # all tests, warnings are errors
uv build --no-sources                    # sdist and wheel
uv run --locked python scripts/check_wheel.py   # install the wheel elsewhere and import it
```

To skip the Docker-backed tests:

```sh
uv run --locked pytest -q -W error -m "not integration"
```

`uv run ruff check --fix` sorts imports.

## Tooling notes

- **Type checking** uses pyrefly, configured in `[tool.pyrefly]`. It checks
  `wire_rpc`, `tests` and `scripts` against Python 3.12.
- **Linting** uses ruff with the pyflakes (`F`) and import-order (`I`) rules,
  configured in `[tool.ruff]`.
- **The lockfile** is generated by uv 0.12.18, the version CI installs. An older
  uv rewrites the whole `uv.lock` in an older format; if your diff touches every
  line, regenerate it with `uvx --from uv==0.12.18 uv lock`.
- **Line endings:** some files use CRLF. Keep each file's existing endings.
- **The wheel check** creates a fresh virtual environment from the Python running
  it. Some older uv-managed Python builds can't do that ("error while loading
  shared libraries: libpython..."); run the script with a newer interpreter if
  you hit it.

## CI

`.github/workflows/tests.yml` runs on pushes and pull requests:

- **The matrix job** runs on Linux, macOS and Windows with Python 3.12, 3.13 and
  3.14: pyrefly, ruff, the tests without Docker, the build and the wheel check.
- **The shared-session job** runs the full suite, including Docker, on Linux.

`.github/workflows/release.yml` publishes releases; see [Releasing](releasing.md).

## Benchmarks

```sh
uv run --locked python scripts/bench.py
```

Results and how to read them are in [docs/benchmarks.md](../docs/benchmarks.md).
Re-run after changes to the request path or transports, and update the doc if
the numbers move meaningfully.

## Documentation

- User docs are in `docs/`. Every claim should match the code; when you change
  behavior, update the page that describes it, and run the examples you touch.
- Docstrings follow the existing style: a one-line summary, then `Args:`,
  `Raises:` and `Usage:` sections where useful.
- Record user-visible changes under `## [Unreleased]` in `CHANGELOG.md`, with
  breaking changes under **Breaking**.
